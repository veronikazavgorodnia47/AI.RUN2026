# ADR-001 — Inventory Read Model: Event-Driven Cache via Kafka and Redis
**Kata:** K 4.W.5 | **Status:** Accepted | **Date:** 2026-07-31
**Deciders:** Architecture lead, Platform engineering, David Park (POS/ops)

---

## Context

Meridian's platform must serve per-SKU inventory availability to web, mobile, and 1,400 in-store POS terminals while SAP ECC remains the inventory source of truth. SAP ECC is an on-prem ERP with batch export cycles of 15–30 minutes; it was not designed as a high-concurrency API backend.

Three options were evaluated (see `00-options.md`):

| Option | Core idea | Key pressure point |
|---|---|---|
| A — Sync SAP reads | Inline SAP query on every inventory check | SAP saturates at Black Friday peak (8,000+ RPS); 200–600ms p95 |
| **B — Event-driven cache** | **Kafka hydrates Redis; cache is the inventory source** | **Structural staleness (15–30 min batch cycle)** |
| C — Commercial OMS | Third-party OMS (Fluent Commerce / OneStock) abstracts SAP | 3–6 month integration; $200–400k/year; high team operability risk |

---

## Decision

**Option B — event-driven read model hydrated from SAP via Kafka, served from Redis.**

SAP ECC publishes `StockUpdated` events via CDC (Debezium) or batch export to a Kafka topic on AWS MSK. A Kafka consumer hydrates an Inventory Read Cache (Redis on ElastiCache). The platform reads inventory exclusively from Redis; SAP is not on the hot path.

Fallback on cache miss or stale TTL: attempt a synchronous SAP adapter call (degraded-latency path). If SAP is unreachable, return `availability: UNKNOWN` with a "confirm with staff" banner — never block the cart or checkout flow.

---

## Consequences

**Positive:**
- Redis reads at 1–5ms p95; platform absorbs Black Friday peak without SAP saturation.
- SAP ECC outages do not bring down inventory checks — degraded mode responds gracefully.
- Cache layer is independently scalable and observable.

**Negative:**
- Structural staleness: cache is up to 15–30 minutes behind SAP. Phantom-stock cancellations are reduced but not eliminated without a CDC path to SAP (requires SAP configuration access that the MRG team may not have).
- Kafka + Redis adds operational burden. Lena Park's junior internal team must own this post-handover.
- If SAP cannot be configured for CDC, the cache is hydrated from batch exports only; staleness is non-negotiable.

---

## Agent-Readable Summary

**Decision:** Inventory availability is always read from a Redis cache hydrated asynchronously from SAP via Kafka. SAP is never queried on the hot path.

**Do not** query SAP ECC synchronously for inventory availability in any user-facing or POS-facing request flow. Direct SAP reads are permitted only as a cache-miss fallback and must include a timeout of 800ms maximum; if SAP does not respond within that window, return `availability: UNKNOWN`.
